# The final allocation grid

One 3x3x3 full-factorial grid. The agent model is held fixed and the question
is where a fixed **token** budget is best spent: on reasoning before answering,
on the notes the agent writes to itself within a run, or on cases retrieved
from earlier runs on other tasks.

| Axis | Config field | Levels | What it answers |
|---|---|---|---|
| reasoning budget | `thinking_token_budget` | 0, 3000, 9000 | how much thinking per attempt pays |
| in-task write budget | `history_write_tokens` | 100, 300, 900 | how much self-summary pays |
| cross-task read budget | `memory.retrieval_tokens` | 0, 4000, 9000 | how much retrieved experience pays |

27 cells = `cells/final-grid-r{R}-w{W}-x{X}.yaml`, all generated by
`make_cells.py`. Regenerate after editing the template:

```bash
python experiments/final_grid/make_cells.py
```

## What is fixed across all 27 cells

`qwen27b` served on one vLLM endpoint; `temperature: 0.5`; `branch_policy:
best`; `run_budget: {type: tokens, limit: 100000}` (matched cost, so the axes
are compared at equal spend); 40 ALE-Bench problems x 5 seeds; official public
eval on every attempt and a single held-out grade at the end; bwrap sandbox;
`chars_per_token: 3.5`; submission through the forced `submit_solution` tool.

The agent is budget-blind and horizon-blind, and every attempt is logged with
its cumulative token spend, so **every run re-reads at any smaller token
cutoff** — the whole cost curve comes out of one sweep. The one thing that
cannot be recovered post hoc is a *larger* cutoff.

## Launch order

1. **Serve the model.** `scripts/serve_vllm.sh`. The r>0 cells additionally
   need `--reasoning-parser qwen3 --reasoning-config` on the server.
2. **Phase 1 — the x=0 plane** (9 memory-free cells). No dependency; these
   runs are the source the cross-task corpus is built from.
3. **Build the corpus** from the phase-1 traces (needs the `models` extra
   and the same `VLLM_BASE_URL` / `VLLM_API_KEY` as the cells; `--cells`
   defaults to the nine x=0 cells):
   ```bash
   arloop-build-corpus --traces-root data/traces \
       --out data/banks/final-loto-corpus --model qwen27b \
       --embed-model Qwen/Qwen3-Embedding-0.6B --nodes-dir data/nodes
   ```
   The x>0 cells name the bank by its DIRECTORY under `banks_root`
   (`memory.bank: final-loto-corpus`); the content hash the build prints
   (`bank-…`) is recorded in every run manifest as `bank_id`, not typed
   into a config. Thousands of LLM calls go into the build, so keep
   `--nodes-dir`: a relaunch then resumes from the cache.
4. **Serve the embedding + reranker models**, one per box:
   `scripts/serve_models.sh`.
5. **Phase 2 — the x>0 planes** (18 cells), which retrieve over that corpus.

## Running a cell

```bash
arloop-grid experiments/final_grid/cells/final-grid-r3000-w300-x4000.yaml \
    --max-workers 14
```

Re-running is idempotent: a cell is done iff an ok run manifest exists for its
(config hash, task, seed), so an interrupted sweep is resumed by the same
command. One driver per box, each pointed at its local server through
`VLLM_BASE_URL`. Exit 0 = complete, 3 = cells still held by another driver,
1 = failures.

**Worker and timeout sizing is per reasoning level, not copied across cells.**
r0 and r3000 run 14 workers at a 600 s client timeout; **r9000 runs 10 workers
at 1800 s** — its calls are long enough to exceed 600 s and time out on every
retry, and the KV cache holds fewer of its longer sequences, so 14 workers
preempt each other. Both are `ops` fields, so changing them preserves the
arm's config hash. `make_cells.py` already sets them per cell.

`smoke.yaml` is a one-task, one-seed, two-attempt cell for checking the wiring
against a live server before committing a plane.
`smoke_memory.yaml` does the same for the cross-task path: build a small bank
from the plain smoke's traces (`arloop-build-corpus --cells final-grid-smoke
--out data/banks/smoke-corpus ...`), start the model server, then run it.

Every path in a cell (`ops.paths.*`, including the `data_env` roots) is
relative to the working directory, so run the commands from the repo root.
`ops` is never part of the arm's config hash: workers, timeouts, paths and
`ops.embedding.server` (per-box model server vs in-process models) can change
without re-keying a cell.

## The reasoning budget fails silently — three ways

An r>0 cell whose budget was not applied returns HTTP 200 with plausible
output and reads identically to r=0 in the ledger. All three must be checked
before a reasoning plane is launched:

1. **`enable_thinking: true` must be sent per request.** The chat template
   defaults to a closed, empty think block, so there is no span to cap and the
   parser misroutes the whole answer into `reasoning_content`. `thinking:
   true` in the cell config is what sends it.
2. **Never enable speculative decoding.** Speculative decoding bypasses the
   budget entirely; the r=3000 and r=9000 planes would run unbounded and the
   axis would read as null. The server must launch with no
   `--speculative-config`.
3. **The server needs `--reasoning-config`** (with a reasoning parser). Without
   it the top-level `thinking_token_budget` request field is accepted and
   ignored.

Verify by the LENGTH of `reasoning_content`, not by
`usage.completion_tokens_details.reasoning_tokens` — that field is not
populated on this serving stack and reports zero at every level, which reads
as a mechanism failure when the mechanism is fine.
